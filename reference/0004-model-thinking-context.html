模型、thinking 与上下文

先判断瓶颈属于能力、推理投入，还是历史负担；不要一次改三个旋钮。

观察到的问题优先动作Pi 操作
模型胜任，只是任务更需要权衡或推理提高 thinking/thinking 或 Shift+Tab
能力或输入类型不匹配，或提高 thinking 后仍卡住切换模型/model / Ctrl+L；scoped models 间用 Ctrl+P
任务没变，但当前可见历史过长先固化关键决定，再压缩/compact [instructions]
需求已经变成无关的新任务隔离上下文/new，或从旧节点 /fork
诊断顺序：推理深度问题 → thinking；能力边界问题 → model；历史负担问题 → compact；任务边界问题 → new/fork。

三个预算不要混成一个

  • Context window：一次请求可容纳的输入与输出总空间；footer 显示当前使用量。
  • Thinking level：请求模型投入多少推理 effort/budget；可用档位由当前模型决定。
  • Output limit：模型单次最多能生成多少 token；不是“剩余上下文”的同义词。
