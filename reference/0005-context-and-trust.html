Context file 与 Project trust

Context file 决定模型持续看到什么；project trust 决定 Pi 是否加载项目代码型配置。两者不是同一条安全边界。

加载规则

来源行为用途
~/.pi/agent/AGENTS.md全局加载跨项目、长期稳定的个人偏好
父目录到当前目录的 AGENTS.md / CLAUDE.md逐层拼接仓库与子目录的事实、约束、命令
AGENTS.override.md只替换同目录的 AGENTS.md / CLAUDE.md该目录需要完全不同的说明时使用
--no-context-files / -nc禁用自动发现排查 context 影响或运行隔离实验

修改后运行 /reload，或重启 Pi。

AGENTS.md 四问

  1. 它是否对这个项目中的多数任务持续有效？
  2. 它是否项目特有，且不能可靠地从代码推断？
  3. 它是否可执行、可验证，而不是模糊愿望？
  4. 它是否值得占用每次请求的上下文？
适合：验证命令、目录边界、固定约束、安全禁令。
不适合：一次性需求、长教程、完整架构说明、任务日志、秘密、会频繁失效的细节。

Trust 到底保护什么？

资源拒绝 project trust 后
AGENTS.md、CLAUDE.md、AGENTS.override.md仍会加载，除非禁用 context files
.pi/settings.json、项目 extensions/skills/prompts/themes、system prompt、项目 packages跳过
模型通过工具执行的本地读写与 shell不受 trust 隔离

Project trust 是启动时的输入加载门，不是 sandbox，也不保证 context file 没有 prompt injection。真正的隔离要依靠容器、VM 或操作系统策略。
