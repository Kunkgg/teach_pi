Pi 定制选择地图

先找最小机制，再考虑安装。Package 是运输箱，不是第五种行为机制。

需求首选机制判断句典型位置
每次都应知道的项目事实Context file“这是持续有效的背景或约束。”AGENTS.md
重复输入的一段任务描述Prompt template“我只想少打字，不改变能力。”.pi/prompts/*.md
按需加载的专业工作流Skill“模型已有工具，只需知道何时、如何使用。”.pi/skills/*/SKILL.md
新增工具、事件、权限或 UIExtension“必须改变 Pi 运行时行为。”.pi/extensions/*.ts
分发上述一种或多种资源Package“我要安装、固定版本或分享一组资源。”package.json 的 pi 字段
从最轻到最重：普通提示 → prompt template → context file / skill → extension。只有当现有工具无法完成任务或需要确定性的生命周期行为时，才升级到 extension。

安装前五问

  1. 它解决了我已经遇到的哪个具体缺口？
  2. 它包含 extension 吗？若包含，它将以我的完整系统权限运行。
  3. 我是否读过入口文件、依赖、安装脚本和网络行为？
  4. 应全局安装，还是只在可信项目中用 -l 安装？
  5. 是否应固定 npm 版本、Git tag 或 commit，以换取可复现性？
