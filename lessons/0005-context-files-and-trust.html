Lesson 0005 · Context & trust

让 AGENTS.md
保持短而可信

本课只完成一个成果：为当前教学仓库写一份短小、持续有效的 AGENTS.md，同时看清 project trust 没有保护什么。

约 18 分钟一份真实 AGENTS.md不新增 package

1. Context file 是每次都交的“项目税”

Pi 启动时会加载全局、父目录和当前目录中的 AGENTS.md 或 CLAUDE.md。同一目录若有 AGENTS.override.md，它会替换该目录的另外两种文件；其他目录的 context 仍照常叠加。修改后运行 /reload 即可重载。完整规则见 Context Files。

判断标准：只有“这个项目里的多数任务都应该知道，而且不能可靠地从代码推断”的信息，才值得进入 AGENTS.md。
适合常驻不适合常驻
经过验证的 lint、test、build 命令今天这一个任务的需求与进度
目录边界与不能违反的项目约束可以从 README 或配置直接读出的长篇说明
非显而易见的安全禁令及适用范围完整教程、聊天记录、TODO 与秘密
项目特有的交付与验证标准“写高质量代码”一类不可验证口号

短不是为了好看，而是为了降低陈旧信息、冲突指令和上下文占用。详细架构应放在普通项目文档里，再从 AGENTS.md 指向它。

2. Project trust 不决定 AGENTS.md 是否加载

这是本课最反直觉的边界：根据官方 Security 文档，即使你拒绝 trust，AGENTS.md、CLAUDE.md 与 AGENTS.override.md 仍会加载；除非使用 --no-context-files 或 -nc。

Project trust 会挡住

项目 .pi/settings.json、extensions、skills、prompts、themes、system prompt 与项目 packages。

Project trust 挡不住

Context file 的文字、工具对本机的读写与 shell 权限，以及仓库内容中的 prompt injection。

因此 trust 只是启动时的输入加载门，不是 sandbox。Pi 的工具和 extension 都以启动它的用户权限运行；需要真正隔离时，应使用容器、VM 或操作系统策略。

当前教学仓库已经保存为 trusted，因为它包含项目级 .pi/skills；但目前没有项目 AGENTS.md。本课只新增 context file，不更改 trust 决策。

3. 用四问过滤每一条

  1. 常驻？多数任务都需要，还是只服务当前任务？
  2. 特有？这是本项目特有信息，还是通用编程常识？
  3. 可执行？Agent 能据此采取明确行动并验证吗？
  4. 值得？它带来的稳定收益值得每次占用 context 吗？

任何一问明显为“否”，先移到普通文档、skill、任务文件或当前提示中，而不是继续扩充 AGENTS.md。

动手：为当前仓库写第一份 AGENTS.md
  1. 回到 Pi，发送下面的只读请求： 
    请读取 MISSION.md、NOTES.md、learning-plan.html、assets/ 和最新的 learning record，
为当前仓库起草 AGENTS.md，但先不要写文件。
限制：不超过 8 条规则；只保留持续有效、项目特有、可执行的信息；
不要复制课程计划，不写一次性任务，不写通用编程常识。
  2. 逐条用“常驻、特有、可执行、值得”四问过滤。若草案过长，用 steering 发送：
    继续收紧：删除能从文件直接推断的内容，并把验证命令保留为可复制执行的形式。
  3. 确认草案至少覆盖：开始工作前读哪些状态文件、lesson/reference 如何复用 assets、修改后如何验证，以及不能擅自改动什么全局状态。
  4. 批准后让 Pi 写入仓库根目录的 AGENTS.md，再运行 git diff --check。
  5. 运行 /reload，确认通知或启动信息显示 context files 已重载。然后执行 git diff -- AGENTS.md，做最后一次人工审查。

完成标准：最终文件保持一屏内；每条都能说明为什么必须“每次可见”。不要为了通过练习，把本课文字整段复制进去。
