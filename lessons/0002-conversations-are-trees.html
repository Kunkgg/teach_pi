Lesson 0002 · Sessions

对话不是直线，
而是一棵树

本课只练一个高频能力：安全地回到旧节点，尝试另一种思路，而不丢掉原路线。

约 10 分钟一次真实分支无需安装

1. 先分清三个对象

Session file

保存在 ~/.pi/agent/sessions/ 的 JSONL 文件。它能容纳整棵树，而非只有当前对话。

Active branch

从根节点到当前 leaf 的一条路径。你当前就在其中一条路径上。

Model context

真正发送给模型的内容：活动路径经过 context 构建与 compaction 后的结果。

Compaction

有损总结旧消息以释放上下文。完整条目仍留在 session 文件，可从树中回看。

最容易产生的误解：模型“现在看不见”一段历史，不代表 Pi “已经删除”了它。上下文窗口与持久化历史不是同一个东西。

2. 为什么这对开发有用？

在线性聊天里，你否定方案 A 再尝试方案 B，A 的大量讨论仍可能占据上下文，并影响模型。Pi 的 /tree 允许你回到共同祖先，在同一个 session 文件中创建 B 分支：

共同问题
├── 方案 A → 实验 → 失败
└── 方案 B → 实验 → 当前 leaf

切换分支时，Pi 可以为离开的分支生成摘要，把值得保留的发现带入新路径。摘要仍然是有损的，所以真正重要的设计决定应写入代码、测试、ADR 或学习记录，而不是只留在聊天中。

动手：就在当前教学会话创建一次分支
  1. 读完本页后回到 Pi，输入 /name pi-learning-journey。
  2. 输入：认知档案为什么不应该永远全部塞进 AGENTS.md？ 等待回答。
  3. 按两次 Esc 打开 /tree，选中刚才那条用户问题。
  4. 编辑为：假设认知档案将增长到 10 万字，为什么不应该全部塞进 AGENTS.md？ 然后提交。
  5. 再次打开 /tree，观察同一父节点下的两条分支；这次取消，不切换。
  6. 运行 /session，观察 session 文件、消息数、token 与成本。

你将亲手验证：选择旧的用户消息时，Pi 会移动到它的父节点，并把原消息放回编辑器；修改后提交会创建新分支，而不是覆写旧历史。

3. 何时不用 /tree？

需求选择原因
在同一问题下比较两种实现/tree替代路线应留在同一棵树中
从过去的问题启动长期独立任务/fork从旧用户消息创建新文件
保存当前路径副本后大胆试验/clone复制当前 active branch 到新文件
只是上下文接近上限/compact总结旧内容，不创建任务分支
