Lesson 0003 · Agent loop

在运行中 steer，
而不是重启

本课只练一个高频能力：当 agent 正在工作时，判断一条新消息应该改变当前路线、排到任务之后，还是立即中止。

约 12 分钟一次消息队列实验无需改设置

1. “正在运行”不是不可打断的黑盒

一次任务通常包含多个模型回合：模型决定调用工具，Pi 执行工具，再把结果交给模型继续判断。等待整个任务结束后才纠正方向，可能已经产生了无用读取、修改或测试。

模型判断调用工具观察结果继续判断

Pi 的消息队列让你在这个循环仍在运行时表达三种不同意图：

Steering

“当前任务方向要变。”Agent 完成本轮正在执行的工具调用后收到消息，再据此继续。

Follow-up

“当前任务照常完成，之后再做这件事。”消息等现有工作全部结束后才送达。

Abort

“现在就停。”中止当前运行，并把排队消息恢复到编辑器。

Dequeue

“这条还没发送的队列消息我要改。”把排队消息取回编辑器。

2. 四个操作，一条判断线

你的真实意图操作送达时机
修正范围、约束或方向输入后按 Enter当前 assistant turn 的工具调用结束后
当前任务完成后再做另一件事输入后按 Alt+EnterAgent 完成全部当前工作后
取回尚在队列里的消息Alt+Up不送达，回到编辑器
立即中止当前运行Escape立即发出中止，并恢复队列消息
最短判断法：改变“正在做的事”用 steering；增加“接下来做的事”用 follow-up；继续执行已经没有价值时才 abort。

Abort 不是事务回滚。已经完成的文件修改、shell 命令或外部请求不会因为按 Escape 自动撤销。中止后先检查工作区与外部状态，再决定恢复或修复。

动手：在当前教学仓库观察队列

先把下面三段文字放在手边，以便快速发送。整个实验只要求分析，不修改文件。

  1. 先发送：
    请对照 MISSION.md 检查 lessons、learning-records 和 reference，报告已覆盖目标、主要缺口与下一步；不要修改文件。
  2. 趁 agent 仍显示工作状态，输入下面这句并按普通 Enter：
    调整当前范围：不要分析 reference，只比较 MISSION.md、lessons 与 learning-records。
  3. 紧接着输入下面这句并按 Alt+Enter：
    当前审查结束后，再单独给我一个不超过 3 条的下一步清单。
  4. 观察：范围修正是否在审查尚未结束时生效；3 条清单是否等到审查完成后才成为下一项工作。

若仓库太小、第一项瞬间完成，请在真实开发项目中换成一个需要多次工具调用的只读任务。不要为了练习而人为加入 sleep。

3. 队列不是任务管理器

默认的 steeringMode 与 followUpMode 都是 one-at-a-time：Pi 每次送达一条并等待响应。也可以在 /settings 中改为 all，但现在没有必要。

  • 队列适合处理执行期间出现的少量新信息，不适合堆放长期 TODO。
  • 如果新需求已经变成独立任务，用新 session、/fork 或项目文件记录，比连续塞 follow-up 更清晰。
  • 如果只是想改一条尚未送达的消息，先用 Alt+Up，不必 abort 整个任务。
