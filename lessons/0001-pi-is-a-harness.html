Lesson 0001 · 心智模型

Pi 是 harness，
不是功能清单

本课只建立一个判断力：面对一个需求时，知道它属于 Pi 的核心循环、说明层，还是运行时扩展层。完成后，你将能避免“先装一堆插件”的迁移陷阱。

约 8 分钟一个决策练习无需安装

1. 三者共有的底层循环

Pi、Claude Code 与 OpenCode 都不是“会写代码的模型”本身，而是把模型放进一个可重复执行的 agent loop：收集上下文，选择行动，执行工具，再把结果交还模型继续判断。Claude Code 官方把它概括为 gather context、take action、verify results；Pi 的默认实现则把可行动作压缩到少量通用工具。

读取上下文模型判断调用工具观察结果

模型负责概率性的判断；harness 负责确定性的工具执行、会话保存、上下文装配与交互界面。换模型不等于换 harness，换 harness 也不等于换模型。

2. Pi 的区别是产品边界，不是另一种魔法

维度PiClaude Code / OpenCode
默认姿态小核心；默认给模型通用文件与 shell 工具提供更多内建工作流、集成或编排入口
缺失能力明确地交给文件、CLI、skill 或 extension更常由产品内建能力、hooks/plugins、MCP 等承接
控制方式通过可读文件和 TypeScript extension 组合自己的 harness在产品规定的配置面内组合已有机制
代价你要自己做选择，并承担第三方代码审查上手路径更明确，但产品预设也更多
关键迁移：不要问“怎样让 Pi 拥有 Claude Code 的全部功能？”先问“我的下一项真实任务缺少什么能力？”Pi 的价值恰恰来自不预先替你回答这个问题。

这不是客观性能排名，而是官方文档呈现的产品取舍。详见 Pi README、How Claude Code works 与 OpenCode Agents。

3. 五个名字，其实只有四种机制

Context file

AGENTS.md 等启动时加载。放持续有效的项目事实、约束与命令。

Prompt template

用 /name 展开重复提示。它节省输入，但不新增工具。

Skill

按需加载的操作说明、脚本和参考资料。它教模型怎样使用已有能力。

Extension

运行在 Pi 进程中的 TypeScript。可新增工具、命令、事件处理、权限门与 UI。

Package 不是第五种行为机制。它是上述资源的安装与分发容器，可以同时装入 extensions、skills、prompts 和 themes。这个区别很重要：看到“package”不能推断它安全或轻量，必须查看里面究竟包含什么。
